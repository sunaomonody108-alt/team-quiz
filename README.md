# チーム対抗クイズ Webアプリ

職場レク用の、スマホで回答するチーム対抗クイズです(設計書 v0.1 に基づく)。
**いまは Phase 1(1日分の進行が通しでできる最小版)まで**です。

- 参加者(スマホ): `…/#/join/day1`(QRコードで配布)
- 司会者兼会場(PC+プロジェクター): `…/#/host/day1`
- 管理画面(投影しない): `…/#/admin`

## 2. 仕組み(Cloud Functions を使わない構成)

設計書の推奨は Cloud Functions でしたが、Functions は有料の Blaze プランが必要なため、
**無料の Spark プランで動く構成**にしています(2026-11-19 決定)。

「サーバー側の検証」は Firestore のセキュリティルール(`firestore.rules`)が担います。

| 守りたいこと | どう守っているか |
|---|---|
| 締切はサーバー基準 | 出題開始時刻をサーバー時刻で記録。回答は「サーバー時刻 < 開始+制限時間」のときだけ保存できる(ルールで判定) |
| 全員答えても時間まで待つ | 「締切」への切り替えも、ルールが「サーバー時刻で時間を過ぎた」ことを確認してから許可 |
| 古い回答で上書きしない | 回答に通し番号(revision)を付け、今より大きい番号のときだけ上書きを許可 |
| 二重加点しない | 採点は「正解発表」ボタンで1回のトランザクションとして実行。段階が「締切」のときしか動かない |
| 連打で段階が飛ばない | どの操作も「今の段階」を確認してから書く。2回目は何もしない |
| 正解を事前に配らない | 正解は管理者しか読めない場所に保存。参加者に届くのは出題中の1問の本文・選択肢だけ |
| 氏名を出さない | 氏名は本人チームと管理者しか読めない。会場画面は氏名を読み込まない |
| 1日目と2日目を分ける | 正解発表・順位は「その日に登録したチーム」しか読めない |
| 点数や順位を改ざんさせない | 進行状態・得点・順位は管理者アカウントしか書けない |

**この構成の割り切り(正直に書きます)**

- 採点は司会者PCのブラウザが行います。司会者PCが正解を読むのは「正解発表」を押した瞬間だけで、画面には発表としてそのまま表示します。
- 締切の切り替え(「回答締切」表示)は司会者画面が開いている必要があります。ただし回答の受付自体はサーバー時刻で自動的に止まるので、司会PCが固まっても締切後の回答は入りません。司会PCは再読み込みすれば続きから進行できます。
- チーム名の「同じ名前」判定(全角/半角・大文字/小文字・空白の違いを無視)はスマホ側で計算しています。アプリを改造すれば回避できますが、職場レクでは問題にならない前提です。ひらがなとカタカナは別の名前として扱います。

## 3. Firebase の準備(最初に1回だけ・ブラウザで操作)

所要30分ほど。**クレジットカード登録は不要**です(Spark プランのまま)。

1. https://console.firebase.google.com/ を開き、Googleアカウントでログイン →「プロジェクトを作成」。
   - 名前は自由(例: `shokuba-quiz`)。Google アナリティクスは「無効」で可。
2. 左メニュー「構築」→ **Authentication** →「始める」→「Sign-in method」タブで次の2つを有効にする。
   - 「匿名」… 参加者用
   - 「メール/パスワード」… 司会者・管理者用
3. 同じ Authentication の「Users」タブ →「ユーザーを追加」で、司会者用のメールアドレスとパスワードを作る。
   作成後に表示される **ユーザー UID**(英数字28文字くらい)をコピーしておく。
4. 左メニュー「構築」→ **Firestore Database** →「データベースの作成」。
   - ロケーション: `asia-northeast1(東京)`
   - 「本番環境モード」で開始
5. Firestore の「ルール」タブを開き、中身をすべて消して、このフォルダの `firestore.rules` の中身を貼り付け →「公開」。
6. Firestore の「データ」タブ →「コレクションを開始」
   - コレクションID: `admins`
   - ドキュメントID: 手順3でコピーした UID
   - フィールド: `note`(string)に `司会者` など何でも
7. 左上の歯車 →「プロジェクトの設定」→ 下の方の「マイアプリ」で「</>(ウェブ)」を選んでアプリを登録(Hostingのチェックは不要)。
   表示される `apiKey` `authDomain` `projectId` `appId` の4つの値を控える。
   - この値は秘密鍵ではありません(誰に見られてもルールでデータは守られます)。
8. 公開先が決まったら、Authentication →「設定」→「承認済みドメイン」に公開先のドメインを追加。
   - GitHub Pages なら `sunaomonody108-alt.github.io`

手順7の4つの値を Claude に渡してもらえれば、ビルド済みファイルを作れます。

## 4. 公開(どちらか)

### A. GitHub Pages(前回の早押しアプリと同じ方法)

`npm run build` で作られる `dist` フォルダの中身をリポジトリにアップロードし、Pages を有効にします。
URLが `#/join/day1` 形式なので、サブフォルダでもそのまま動きます。

### B. Firebase Hosting

Windows に Node.js を入れ、このフォルダで `npx firebase login` → `npx firebase deploy --only hosting,firestore:rules`。
(`.firebaserc` の `demo-quiz` を自分のプロジェクトIDに変える)

自分のPCでビルドする場合は `.env.example` を `.env.local` にコピーして手順7の値を入れ、`npm install` → `npm run build`。

## 5. 当日の流れ

**事前(前日まで)**

1. 管理画面 → 「イベントを初期化」(初回のみ)
2. 問題を登録(JSONを貼り付けて「貼り付けた問題を登録」)。登録後の一覧で正解・解説を確認
3. 管理画面の「リハーサル用:この日のデータをすべて消す」を使って、何度でも通し練習できる

**本番**

1. 会場PCで `#/host/day1` を開いて管理者アカウントでログイン → プロジェクターに複製表示
2. 「受付を開始」→ QRコードが出る → 各チームの代表者が登録
3. 「受付を締め切って開始」(以後は登録できない。問題もロックされる)
4. 各問: 「出題開始」→ 時間切れで自動的に「回答締切」→「正解発表」→「次の問題へ」
5. Q5・Q10・Q15 の後は「途中順位へ」で上位3位を表示(スマホには自チームの順位と正解数)
6. Q20 の後は「結果発表へ」で、その日の上位3位を表示

管理画面は投影しない別のPC/スマホで開いてください(正解と氏名が表示されます)。

## 6. 問題データ(JSON)の形式

20問ちょうど・`position` は 1〜20。制限時間は種類から自動(4択20秒・並べ替え30秒)。
選択肢IDは登録時に `c1`〜 に振り直すので、元のIDに答えのヒントが入っていても漏れません。

```json
[
  {
    "position": 1,
    "type": "multiple_choice",
    "prompt": "日本で一番高い山は?",
    "choices": [
      { "id": "a", "label": "富士山" },
      { "id": "b", "label": "北岳" },
      { "id": "c", "label": "奥穂高岳" },
      { "id": "d", "label": "槍ヶ岳" }
    ],
    "correctChoiceId": "a",
    "explanation": "富士山は標高3,776m。",
    "imageUrl": "(任意)https://…",
    "imageAlt": "(任意)画像の説明",
    "difficulty": "(任意)易", "genre": "(任意)雑学", "tone": "(任意)意外性"
  },
  {
    "position": 4,
    "type": "ordering",
    "prompt": "小さい順に並べてください",
    "choices": [
      { "id": "x", "label": "100" }, { "id": "y", "label": "1" },
      { "id": "z", "label": "1000" }, { "id": "w", "label": "10" }
    ],
    "correctOrderIds": ["y", "w", "x", "z"],
    "explanation": "桁が増えるほど大きい。"
  }
]
```

- 並べ替えの `choices` の順番が、スマホに最初に表示される並びです(正解と同じ並びでも回答できます)。
- 画像は今は「インターネット上の画像URL」のみ。画像アップロードは Phase 2 です。
  (注: 新しい Firebase プロジェクトの Cloud Storage は Blaze プランが必要になったため、無料のまま画像を扱う方法を Phase 2 で決めます)

## 8. テスト

```bash
npm install
npm test           # 単体テスト(順位計算・採点・問題データ検証)… Emulator 不要
npm run test:emu   # Firestore Emulator 上でルールと進行を検証(Java が必要)
```

画面を手元で試す(本物の Firebase は使わない):

```bash
npm run emu        # 別ウィンドウで起動したままにする
npm run emu:seed   # テスト用管理者 admin@example.com / password を作る
npm run dev        # http://localhost:5173/#/admin を開く
```

`e2e/run-e2e.mjs` は、司会PC1台+スマホ3台をブラウザ自動操作でQ1〜Q5(途中順位)まで通すスクリプトです。
